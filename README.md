# DragonOS ACARS Monitor (двухчастотный)

Графический монитор ACARS, который объединяет GNU Radio потоковую схему и PyQt‑интерфейс. Поддерживает:

- **Локальный приём RTL‑SDR + GUI** (всё на одном ПК).
- **Офлайн‑анализ** уже сохранённых логов (без SDR).
- **Разнесённый приём**: Raspberry Pi принимает и фильтрует каналы, передаёт узкополосный IQ по UDP, а операторский ПК демодулирует и декодирует ACARS.

## Коротко о сигнале

Встроенная схема соответствует GRC‑потокам `tx.py`/`rx.py`:

- **Sample rate SDR**: 240 kHz
- **Два канала**: 131.725 MHz и 131.825 MHz
- **Фильтрация**: LPF 5 kHz / 6 kHz, decim=5 → **48 kHz** на канал
- **AM демодуляция**: `channel_rate=48 kHz`, `audio_decim=1`
- **ACARS decoder**: `acars.acars(4, <log>, False)`
- **UDP**: комплексные `gr_complex`, MTU 1472

Порядок каналов всегда фиксирован:

1. 131.725 MHz → UDP порт 52001
2. 131.825 MHz → UDP порт 52002

## Структура проекта

- `dragonos_acars_app.py` — основной GUI и потоковая схема (локальный приём, UDP‑источники, форвардер).
- `acars_gui.py` — автономный GUI‑просмотрщик логов, парсер ACARS, карта, статистика.
- `tx.py` — GRC‑схема передатчика (узкополосный IQ по UDP).
- `rx.py` — GRC‑схема приёмника (UDP → AM → ACARS лог).

## Требования

- Python 3.8+
- PyQt5
- GNU Radio 3.10 + SoapySDR + блок `acars`
- Matplotlib (графики активности/спектр)
- Cartopy (карта)

Проверка основных зависимостей:

```bash
python3 -c "import PyQt5, gnuradio, acars"
```

## Режимы работы

### 1) Локальный приём RTL‑SDR + GUI

```bash
python3 dragonos_acars_app.py
```

Что происходит:

- При первом запуске GUI попросит выбрать файлы логов (для обоих каналов).
- После подтверждения путей запускается приёмник.
- Обновление GUI — каждые 5 секунд (можно отключить).

### 2) Офлайн‑анализ логов

```bash
python3 dragonos_acars_app.py --offline --log /path/log1.txt --log /path/log2.txt
```

Если `--log` не указан, GUI предложит выбрать файлы.

Альтернатива — автономный просмотрщик:

```bash
python3 acars_gui.py --log /path/log1.txt --log /path/log2.txt
```

### 3) Разнесённый приём: Raspberry Pi → ПК оператора

**Pi (форвардер, без GUI):**

```bash
python3 dragonos_acars_app.py \
  --forward-only \
  --udp-dest OPER_HOST:52001 \
  --udp-dest OPER_HOST:52002
```

**ПК оператора (приём UDP + GUI):**

```bash
python3 dragonos_acars_app.py \
  --udp-source 0.0.0.0:52001 \
  --udp-source 0.0.0.0:52002 \
  --log /path/acars_725.txt \
  --log /path/acars_825.txt
```

Важно:

- Порядок `--udp-dest` и `--udp-source` должен совпадать с каналами.
- Логи сохраняются локально на ПК оператора.

## Управление в GUI

- **Пауза/Возобновить** приёмник.
- **Очистить лог** (архивируется с временной меткой).
- **Усиление** (активно только при локальном приёме SDR).
- **Карта** — становится активной при появлении координат.
- **Выгрузить лог** — сохраняет объединённый лог.

Вкладки:

- Таблица сообщений
- Raw log
- Байтовая раскладка
- Статистика бортов
- Параметры ACARS
- Спектр/активность каналов

## Частые проблемы и решения

### `gr::vmcircbuf :error: shmat (3): Invalid argument`

Это предупреждение GNU Radio о shared memory. На Windows/WSL оно часто появляется, но обычно не ломает работу.

Варианты:

- **Windows/WSL**: игнорировать или отключить vmcircbuf.
- **Linux/DragonOS**: увеличить `/dev/shm` или лимиты shm.

### Нет данных в GUI

Проверь:

- Порты 52001/52002 открыты и не заняты.
- Порядок UDP‑источников совпадает с каналами.
- Файлы логов реально создаются (права на запись).
- SDR центрирована и исправно работает (локальный режим).

### Карта/графики не работают

Установи зависимости:

```bash
pip install matplotlib cartopy
```

## CLI‑опции (основные)

- `--offline` — только просмотр логов, без SDR.
- `--log PATH` — путь к логу (можно несколько).
- `--udp-source HOST:PORT` — получать IQ по UDP (оператор).
- `--forward-only` — форвардер SDR → UDP без декода (Pi).
- `--udp-dest HOST:PORT` — куда отправлять IQ в режиме форвардера.

## Примечания

- Логи по умолчанию: `/tmp/log_acars_131_725.txt` и `/tmp/log_acars_131_825.txt`.
- Можно менять пути через GUI меню «Файл лога…».
- Встроенный GUI полностью сохраняет функционал локального приёма и офлайн‑анализа.
